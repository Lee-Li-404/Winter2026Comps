About the Project

In 1988, Robert T. Morris released the first widely known internet worm. The program spread rapidly across the early internet and infected thousands of machines. Because of a flaw in its infection logic, many systems became overloaded by multiple worm instances, bringing large parts of the network to a halt.

For our Computer Science Comps project, we built a sandbox environment and recreated key aspects of this historic attack in a safe and controlled setting.

Our Simulation

Our environment recreates a small network of machines similar to those present on the early internet.

  • Docker containers simulate multiple computers
  • Each container runs a SIMH emulator
  • SIMH boots the historical 4.3BSD UNIX system
  • Network services such as sendmail and fingerd are enabled

Within this simulated network we implemented worm programs inspired by the original Morris Worm in order to study how infections propagate across vulnerable systems.

The Morris Worm

In November 1988, a graduate student named Robert T. Morris released a program onto the early internet that would later become known as the Morris Worm. It is widely considered the first major self-propagating worm to spread across the internet.

At the time, the internet was still small and largely used by universities and research institutions. Security was not a major design concern, and many systems trusted each other by default.

The Early Internet

In 1988, the internet consisted of roughly sixty thousand connected machines. Many of these systems ran the UNIX operating system, particularly the 4.3BSD distribution used at universities and research labs.

Network services were often exposed directly to the internet and assumed that incoming connections were trustworthy. This environment made it possible for a self-propagating program to move quickly between machines.

How the Worm Spread

  • Sendmail debug mode allowed remote command execution
  • The fingerd service contained a buffer overflow vulnerability
  • Weak passwords allowed login through remote shell services

By combining these techniques, the worm could compromise a machine and then install a new copy of itself, allowing the infection to continue spreading across the network.

The Bug That Took Down the Internet

Morris attempted to prevent the worm from infecting the same machine multiple times. However, the mechanism designed to avoid reinfection did not work correctly.

As a result, machines frequently became infected repeatedly. Multiple copies of the worm would run simultaneously, consuming system resources and causing many computers to slow down or crash.

Aftermath

The Morris Worm led to the first major legal case involving computer hacking in the United States. Robert Morris was later prosecuted under the Computer Fraud and Abuse Act.

The incident also prompted the creation of the first Computer Emergency Response Team (CERT), which was designed to coordinate responses to large-scale cybersecurity incidents.

Simulation Environment

Project Repository: github-link

To study the behavior of the Morris Worm safely, we built a sandboxed network environment that recreates important aspects of the early internet. Instead of reproducing the worm exactly, our goal was to build a system similar enough to observe how self-propagating malware spreads.

Fingerd Buffer Overflow

Another vulnerability exploited by the Morris Worm involved the fingerd service.

echo username | nc target_machine 79

The original fingerd implementation used the unsafe C function gets().

char line[512]; gets(line);

Because gets() does not check input length, attackers could overflow the buffer and overwrite the return address on the stack.

Sendmail Exploit

Another propagation method involved exploiting a debugging feature in the sendmail mail transfer service.

telnet node-1 25 DEBUG rcpt to:<"| sed '1,/^$/d' | /bin/sh">

This converts the SMTP session into a remote command execution channel. The worm then uploads its source code and compiles it on the target system.
